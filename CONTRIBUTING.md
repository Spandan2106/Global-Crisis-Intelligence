# Contributing to Global Crisis Intelligence 🌍

Thank you for your interest in contributing to **Global Crisis Intelligence**!

Global Crisis Intelligence is an interactive intelligence dashboard designed to bring global events, geopolitical developments, conflict information, economic indicators, and AI-assisted insights together in one place.

Contributions that improve accuracy, usability, performance, accessibility, security, and maintainability are welcome.

## 🚀 Getting Started

1. Fork the repository.
2. Clone your fork:

   ```bash
   git clone https://github.com/YOUR_USERNAME/Global-Crisis-Intelligence.git
   cd Global-Crisis-Intelligence
   ```

3. Create a branch for your changes:

   ```bash
   git checkout -b feature/your-feature-name
   ```

4. Review the existing project structure and documentation before making changes.
5. Install dependencies using the package manager and instructions specified by the project.
6. Configure the required environment variables using the provided example configuration, if available.

**Important:** Do not commit API keys, access tokens, passwords, private credentials, or other secrets.

## 💡 Ways to Contribute

You can contribute by:

- Fixing bugs and improving application stability.
- Improving interactive maps and 3D globe visualizations.
- Enhancing geopolitical news aggregation and event presentation.
- Improving AI-assisted analysis, summaries, and error handling.
- Optimizing performance, loading times, and API requests.
- Improving responsive design and accessibility.
- Strengthening input validation and application security.
- Improving documentation, setup instructions, and developer experience.
- Adding automated tests and improving existing test coverage.

Before starting a major change, open an issue to discuss the proposed approach.

## 🛠️ Development Guidelines

Please follow these principles when contributing:

- **Keep changes focused:** Each pull request should address one main concern.
- **Write readable code:** Prefer clear names, small functions, and maintainable implementations.
- **Follow existing conventions:** Match the project's established architecture, formatting, and naming patterns.
- **Handle failures gracefully:** Account for unavailable APIs, network errors, missing data, and unexpected responses.
- **Protect sensitive information:** Keep credentials in environment variables and never expose secrets in client-side code.
- **Respect external APIs:** Follow provider documentation, usage limits, attribution requirements, and applicable terms.
- **Preserve data integrity:** Validate incoming data and avoid presenting fabricated or unverified events as facts.
- **Document important changes:** Update relevant documentation when behavior, configuration, or setup requirements change.

## 🐛 Reporting Bugs

Before opening a bug report, check whether the issue has already been reported.

Include the following information:

- A clear and descriptive title.
- Steps to reproduce the issue.
- Expected behavior.
- Actual behavior.
- Relevant error messages or logs, with sensitive information removed.
- Browser, operating system, and environment details, where relevant.
- Screenshots or recordings, when they help explain the issue.

Never include private API credentials, personal information, or confidential data in an issue.

## ✨ Suggesting Features

Feature suggestions are welcome when they improve the project's usefulness, reliability, or user experience.

Please describe:

- The problem the feature would solve.
- The proposed behavior.
- Why it would benefit users.
- Any relevant examples, mockups, or technical considerations.

For substantial changes, discuss the idea in an issue before implementing it.

## 🔄 Submitting Pull Requests

1. Create a branch from the latest appropriate base branch.
2. Make your changes and keep the diff focused.
3. Test the affected functionality.
4. Run the available linting, type-checking, build, and test commands, where applicable.
5. Update documentation if necessary.
6. Commit your changes with a descriptive message.
7. Push your branch and open a pull request against the repository's default branch.

A useful pull request description should include:

- **Summary:** What changed?
- **Motivation:** Why is the change needed?
- **Implementation:** How was it implemented?
- **Testing:** What checks were performed?
- **Screenshots:** Include them for meaningful visual changes.

Please disclose any known limitations and ensure that your contribution does not introduce unrelated changes.

## 🌐 Data Accuracy and Responsible Intelligence

Because this project presents global and geopolitical information:

- Prefer credible, attributable sources.
- Preserve source links and timestamps where available.
- Distinguish verified information from analysis, estimates, and AI-generated interpretations.
- Avoid presenting predictions or AI-generated conclusions as established facts.
- Clearly handle missing, delayed, or conflicting information.
- Respect source licensing, privacy, and applicable terms of service.

## 🤝 Code of Conduct

Contributors are expected to communicate respectfully and constructively.

Harassment, discrimination, personal attacks, and deliberately disruptive behavior are not acceptable. Focus discussions on the work, technical evidence, and ways to improve the project.
